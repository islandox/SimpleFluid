# Matched boundary-layer meshes

The water verification cases now use explicit, shared Cartesian edge files
generated by the production `BoundaryLayerMeshFactory`. The factory runs on a
native mesh before any `MeshHandle`, fields, or cached operators are created.
Both CFD implementations consume the same coordinates; OpenFOAM uses exact
one-cell hexahedral blocks, with no separate grading approximation.

| Case / mesh | Cells | Layers per refined end | Growth | First cell in x / z |
| --- | ---: | ---: | ---: | --- |
| Bottom convection, default | 28 × 1 × 36 = 1008 | 6 | 1.25 | 0.296 / 0.222 mm |
| Bottom convection, fine | 40 × 1 × 52 = 2080 | 8 | 1.25 | 0.168 / 0.126 mm |
| Dispersed bubble column | 1 × 1 × 44 | 6 | 1.30 | Unrefined / 7.839 mm |
| Planar ALE column | 1 × 1 × 12 | 4 | 1.30 | Unrefined / 40.407 mm |

The convection layer stacks cover 3.333 mm at each x wall and 2.5 mm at each
z wall. The interior base grids are 24×32 and 36×48, respectively; source
boundaries at x=W/3, x=2W/3, and z=H/8 remain cell faces on both grids.
The integrated heat and H2 production therefore remain unchanged. Adjacent
cell-width ratios, including stack-to-interior transitions, remain below 1.5.

The bubble and ALE fixtures retain their one-dimensional physical limits.
Their end grading exercises transport/escape or moving-volume operators; it
does not introduce a hydrodynamic wall layer into a prescribed-flow bubble
model or a uniform-heating ALE model. The convection case resolves actual
wall-normal momentum and temperature gradients.

## Run and regenerate

The normal case launchers use `mesh.dat`. Select another compatible mesh for
both solvers with one environment variable:

```sh
SIMPLEFLUID_BUILD_CONFIG=Release \
SIMPLEFLUID_VERIFICATION_MESH="$PWD/verification/openfoam/bottomHeatedBubblyConvection/mesh_fine.dat" \
  verification/openfoam/bottomHeatedBubblyConvection/run_comparison.sh \
  build/verification/boundary-layer/fine
```

The original 192-cell convection grid is retained as `mesh_uniform.dat` for
controlled comparisons. Other physical/source/time parameters are shared and
unchanged across these meshes. Each run snapshots the selected coordinates
and a derived `manifest.json`, including actual cell IDs, counts, edge arrays,
and spacing statistics. Comparisons must use that run manifest, especially
when replotting a non-default grid.

Regenerate coordinates from the native factory using:

```sh
cmake --build --preset GCC-Release --target verification_boundary_layer_mesh
build/gcc/bin/Release/verification_boundary_layer_mesh \
  bottomHeatedBubblyConvection medium verification/openfoam/bottomHeatedBubblyConvection/mesh.dat
build/gcc/bin/Release/verification_boundary_layer_mesh \
  bottomHeatedBubblyConvection fine verification/openfoam/bottomHeatedBubblyConvection/mesh_fine.dat
build/gcc/bin/Release/verification_boundary_layer_mesh \
  dispersedBubbleFlow medium verification/openfoam/dispersedBubbleFlow/mesh.dat
build/gcc/bin/Release/verification_boundary_layer_mesh \
  planarALE medium verification/openfoam/planarALE/mesh.dat
```

Each gallery includes a `mesh` figure in addition to the field/error figures.
Cell IDs, inventory integrals, temperature averages, wall heat fluxes, and
analytic bubble-profile errors use actual cell positions, volumes, and face
distances. The plotter verifies output cell bounds against the declared mesh
(with the accepted axial stretch for ALE).

## Algebraic accuracy and qualification

The graded convection source initially exposed a transport-accuracy problem:
with the old internal default tolerance of 1e-10, the near-zero early escape
could be overwhelmed by a tiny positive inventory error. The strict inventory
check correctly rejected that result at step 4. The case now requests
`gas_transport_tolerance=1e-14` in both implementations. SimpleFluid exposes
the corresponding optional `RadiolyticGasOptions::transport_solver_tolerance`
(`radiolytic_transport_solver_tolerance` in a database), retaining 1e-10 as
the default for existing callers. The physical inventory checks are unchanged.
A short graded-transport regression covers the previously failing phase.

Mesh quality and two-grid sensitivity are distinct from mesh independence.
The convection medium/fine comparison holds the 0.02 s time step fixed to
isolate spatial changes; it is not a time-convergence study or experimental
validation. Previous performance numbers refer to the 192-cell uniform grid
and its earlier transport tolerance, not these refined cases.

## Focused results (2026-09-08, Release / OpenFOAM v2606)

All seven paired comparisons passed: uniform/default/fine convection plus
steady/transient graded bubble-column and ALE cases. The convection meshes
have zero non-orthogonality; their maximum aspect ratios are 9.01 (default)
and 15.87 (fine), and OpenFOAM `checkMesh` reports `Mesh OK`.

| Convection result at 20 s | Uniform, 192 cells | Graded, 1008 cells | Fine, 2080 cells |
| --- | ---: | ---: | ---: |
| SimpleFluid maximum T, K | 302.075 | 303.481 | 303.691 |
| OpenFOAM maximum T, K | 302.002 | 303.484 | 303.706 |
| SimpleFluid peak speed, mm/s | 7.585 | 9.368 | 9.981 |
| OpenFOAM peak speed, mm/s | 7.567 | 9.354 | 9.980 |

The maximum cross-solver cell-temperature difference over the full history
decreased from about 0.145 K on the uniform grid to 0.0145 K on the finest
grid. This better agreement does not establish mesh independence: default to
fine still changes SimpleFluid's maximum temperature rise by 6.04%, peak speed
by 6.54%, peak gas fraction by 1.87%, and cold-wall heat loss by 4.08%.
Further refinement is needed before claiming mesh-independent results.

`mesh_refinement.py` produces a numerical table and SVG/PNG/PDF sensitivity
figure from retained run directories, verifying identical physical/time input
dictionaries. It computes cold-wall heat loss from the actual graded cell
dimensions and temperatures:

```sh
python3 verification/openfoam/mesh_refinement.py \
  --run uniform=/path/to/uniform-run --run graded=/path/to/default-run \
  --run fine=/path/to/fine-run --output /path/to/mesh-sensitivity
```
